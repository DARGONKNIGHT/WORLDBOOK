# 《地球：现实人生》· 离线可玩浏览器版

本项目以 WORLDBOOK v34 为当前规则依据（继承v33证据门槛），新增独立 **S级单机试玩游戏**。这是一个可操作的游戏原型，不是实时地球数字孪生，也不会改动正式冻结状态。原生 HTML / CSS / JS，无需账号或安装依赖。

## 开始游玩

**单文件方法（推荐）**：下载 [earth-realism.html](earth-realism.html)（GitHub 文件页右上角 Download raw file，或从 [raw 地址](https://raw.githubusercontent.com/DARGONKNIGHT/WORLDBOOK/main/game/earth-realism.html)保存为同名 .html），双击用现代浏览器打开，按提示创建角色。

**在线部署**：GitHub Pages 成功启用且手动触发发布工作流成功后，预计网址是 https://dargonknight.github.io/WORLDBOOK/ 。实际是否可用须以 GitHub Pages/Actions 状态为准；若发布工作流因为 Pages 尚未启用而失败，先进入 Settings → Pages → Build and deployment，将 Source 设为 GitHub Actions，再手动运行 Game · Publish to Pages (after enablement)。

**源代码方法**：下载本仓库 ZIP，解压后双击 game/index.html；该入口会引用同目录 engine.js、app.js、style.css。两个入口都可离线玩。

## Game 5.0 · NPC经济执行流程（EXE主交付）

- **世界书**：[v34证据门槛与社会经济规则](../worldbook/v34.md)。此版增量保留31名S级NPC、正式世界2026-10-09冻结和未知资料不得推断原则。
- **操作**：打开Windows游戏，在「社会后台」启动自主NPC并推进时间（点击等待1小时/4小时也会按10分钟粒度结算，延迟消息与自主判断不会集中挤到最后一刻），让马志强与高鹏这组已有维修合作伙伴自主形成工作协商并互相回复。社会后台出现status=discussed的工作案例CASE-id后，使用「经济执行层 · S级测试账本」输入**假设的**价格、经营者测试余额和合作方测试余额。这些金额不代表真实个人或企业资产。
- **自主行为**：高鹏知晓已讨论事项后可以决定报价；报价经消息延迟传到马志强后，后者决定接受/拒绝，且余额不足不能接受；高鹏收到原则接受消息后才可能报告模拟完成。只有当报告送达且用户在元视角明确确认S级模拟履约，才能点击「授权S级成对记账」。
- **账目**：每次通过审核的S级资金结算写入唯一交易ID和两个正负金额分录，双方余额严格守恒。报价不等于合同，报告不等于真实履约，S级付款不代表银行卡实际划转。UI的日志是**元视角**，不会把NPC私人资金披露给玩家角色。
- **EXE**：新版自动打包仍输出Work/EarthRealism.exe，_internal及所有编译中间文件/日志/存档归属Work。Windows Actions成功发布后从Artifacts下载完整exe依赖包，不能单独移动exe。game/VERSION与CHANGELOG顶层同步更新；旧存档schema=2无需清空，经济层字段在首次使用时建立。

## Game 4.0 · Windows EXE（今后版本主要交付）

**标准下载方式：** 打开[Windows EXE构建工作流](https://github.com/DARGONKNIGHT/WORLDBOOK/actions/workflows/windows-exe.yml)，选择最近一个成功的运行，从 Artifacts 下载 `EarthRealism-Windows-v4-Work`。解压到一个叫 `Work` 的目录，使目录结构如下：

```text
Work/
├── EarthRealism.exe      ← 双击启动
├── _internal/            ← Python依赖、网页引擎（必须和exe同目录）
├── README.txt
├── logs/                 ← 运行日志（首次启动时创建）
├── saves/                ← autoplay.json：桌面版自动存档
└── tmp/                  ← 本地临时数据
```

点击 `Work/EarthRealism.exe` 会在本机启动`127.0.0.1:8765`游戏服务和你的默认浏览器。Windows不能有另一个程序占用该端口。**不需要Python或命令行，游戏核心在EXE打包依赖中**；可选真实AI语言模型依然需自行安装Ollama（不自动下载模型），见下方Game 3.0步骤。

**构建与目录约束：** 在Windows环境中安装PyInstaller后从仓库根目录运行：

```powershell
python -m pip install "pyinstaller>=6.10,<7"
python scripts/build_windows_exe.py --output Work
python scripts/build_windows_exe.py --output Work --verify-layout
```

构建中间文件均存储于同一 `Work/` 下：`.build/`、`.spec/`、`.cache/`、`tmp/`、`.stage/`；运行依赖为 `_internal/`，运行日志在`logs/`。使用`--onedir`形式，所以程序运行时不会把自身解压到系统临时目录。`Work/`被.gitignore排除，EXE通过GitHub Actions产物交付，不将二进制直接提交到源码仓库。后续版本继续遵循此相对路径规则。

**新增社会事件：** 游戏运行时，已知家人或同事可基于当前工作/家庭日程主动提出协商，消息到达后另一方才有机会独立审阅和回复；角色的岗位责任、已有消息、S级时间和事件状态都会影响结果。在「社会后台」查看状态与审计。这是有限事务链，**不等于已经核实或完成工作合同、劳资支付、社会福利审批或财务结算**。

**存档位置：** 桌面版在本机 `Work/saves/autoplay.json` 原子写入与恢复存档，同时保留浏览器本地缓存作为兼容备份。建议仍定期从游戏导出JSON。旧网页单文件保留用于兼容与调试，不再作为新版主要发行介质。


## 游戏 3.0：31名自主智能体、实时模拟与可选真实AI

**建议先使用离线模式试玩。** 进入「社会后台」→「31名独立NPC · 持续思考模式」，选择「离线 · 有限决策器」，选择游戏时钟倍率后点击「启动实时世界」。页面打开且运行时，31名NPC维护自己的目标、需求、私有记忆和计划，约每30游戏分钟重新做出自主选择。点击「暂停实时世界」停止。所有自主事件为玩家外视角，不会自动变成主角已知信息。**离线决策器不是语言模型。**

**启用真正的本机语言模型推理**（可选）：

1. 在电脑上安装并运行 [Ollama](https://ollama.com/)，打开终端执行 `ollama pull qwen2.5:3b`（安装成功并拥有合适设备内存时）。
2. 下载/克隆本仓库，在仓库根目录执行 `python3 game/agent_server.py`；这是127.0.0.1上的本地网页和AI代理，无需云端密钥。可用环境变量 `OLLAMA_MODEL` 修改已下载的模型名称。
3. 在浏览器打开 **http://127.0.0.1:8765/**（不是双击file://的单文件版），创建或导入存档，在社会后台选择「本机 · Ollama语言模型」、速度1分钟/秒，点击「启动实时世界」。
4. NPC的规则决策始终持续运行；本地模型逐个异步审议NPC的可行动作。审计日志里 `provider=rules` 与 `provider=ollama` 严格区分。若模型未启动或输出非法，会显示错误，**不假装LLM已经作了决定**。

### 设计界限与成本

- 游戏时钟的1分钟/秒是可选模拟倍率，不代表外部真实世界时钟。浏览器关闭或电脑断电后不会继续运行或追算遗漏的时间；重新打开默认暂停。此举保护正式世界书冻结条件。
- 每个NPC拥有不同目标、需求与可知消息，但不是24小时自由进行心智活动，也没有真实生物心理。语言模型以单进程资源按顺序请求，并非31个独立大模型实例；硬件差时等待会比较长。复杂度、响应和资源消耗依实际模型、GPU/CPU而定。
- 当前可选择的动作仅包括工作、休息、家庭事务、已知亲属/同事沟通、学习、推迟非必要事项等；模型无权创造财务交易、名额、合同、亲密关系或法律事实。
- 不需要任何API Key。localhost服务不应暴露给公网，也不要向模型输入真实他人的隐私资料。离线版仍保留完全不需要Ollama的可玩路径。
- 所有变更及已知不足详见 [根目录更新日志](../CHANGELOG.md)，最新版本置于最上方。

## 游戏 2.0 · 人物自主活动和互动改进

进入 **「社会后台」→「人物自主活动」**，可切换自主NPC是否随时间结算、选择“按状态变化/逐小时”的审计精度、点选单个人物查看当前S级日程与决策依据，或直接点击 **“所有NPC自主运行1小时/4小时”**。这会推进游戏时钟，不是后台实时运行；这里的信息是玩家外审计视角。

在 **「我的生活」→「参加公共活动」** 中，只有处于同区、可公开接触时段的成年人物才可能碰面，且**并不保证一定有人**。人物不会自动加好友：在 **「人物与联系」→「本次分支的相遇记录」** 选择 **“礼貌询问联系方式”**，对方可以接受或拒绝。被拒后同一场景不得重复索取。

消息按 **发送→网络送达→人物阅读→可能回复** 多阶段处理。人物忙工作/家庭/休息时并不立即读消息，借款/见面/工作/维修等请求获得不同回应，也可能保持沉默。家庭成员和已建立的同事关系会在**后台进行S级协商与信息传递**，不会自动透露给主角。

已有v1浏览器存档会尝试升级到v2数据结构；建议先导出旧JSON备份。每次游戏修改都会更新仓库根目录的 [更新日志（最新在上）](../CHANGELOG.md)。

## 已实现功能

- 创建角色：姓名、年龄、北京16区开局地点、具体开局时刻、职业、目标、可支配现金（可留空，未知不是零）。
- 行动：观察街区、S级公共活动偶遇、整理计划、处理既有工作、休息、等待；只有主动操作才推进游戏时钟。
- 出行：玩家给出假设耗时与登记的支出，先出发，时间经过后才抵达；无实时路况/真实票价承诺。
- NPC：从世界书导入31人名单与已有关系，以职业、日程、轮班、家庭和休息优先级安排有限自主事务，并在已知家人与同事间延迟传播消息。模拟地点/日程是显式S级假设。
- 联系与消息：同区偶遇、交谈、交换联系方式分离，且对方可以拒绝；发送、送达、阅读、回应各自有时间和信息条件。幕后活动不自动变成玩家知识。
- 保存：尝试在浏览器 localStorage 自动保存，可导出JSON和导入恢复；完全离线，不会同步云端。
- 玩家视角事件日志与可选的社会后台审计视角分离。

## 尚未实现的范围

这是可游玩的早期版本，不是将原有 v14 Python引擎、v15—v33 所有模块全部移植。暂不具备真实 OSM 全北京市寻路、真实 GTFS 时刻、签证社保税务核算、可信银行转账、住房合同处理、完整跨域资金守恒、实时生活资料及31人全面自主日常。对于未核实数据严格保持 U 级，而不是捏造数值。v2—v12世界书早期全文仍有来源缺口。

浏览器存档模式为 S_INDEPENDENT_PLAYTHROUGH，原始正式世界仍被冻结：2026年10月9日，玩家不存在、未指定具体游戏时刻、历史账本为空。**只有你在新游戏里明确创建的分支才推进时间。** 顺义区前礼务村是观察样本，不是预设玩家住址。

**事实等级**：R=已核实的真实信息；S=明确的模拟设定、人物和剧情；U=未知或未核实。游戏中的偶遇、NPC活动及路线耗时均为S。

## 自检与可重复构建

在仓库根目录运行以下命令：

- node --test game/tests/*.test.cjs
- python3 -m unittest discover -s game/tests -p "test_*server*.py" -v
- node --check game/engine.js
- node --check game/app.js
- node --test game/tests/engine.test.cjs
- python3 scripts/build_standalone_game.py --check

编辑多文件源码后，运行 python3 scripts/build_standalone_game.py 更新独立单文件发布版。自动测试工作流见 .github/workflows/game-tests.yml；Pages发布为独立手动工作流 .github/workflows/game-pages.yml。单机游戏属于界面层，不自动升级核心世界书版本。
